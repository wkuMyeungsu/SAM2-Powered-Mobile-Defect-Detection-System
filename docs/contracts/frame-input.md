# 프레임 입력: 휴대폰 → gateway

- 상태: **초안 (합의 전)**
- 확인: 우진(gateway) · 명수(web, QR 표시)

## 접속

휴대폰 브라우저는 HTTPS 주소에서만 카메라를 열어 준다. 그래서 gateway 컨테이너 안에서 cloudflared 임시 터널을 띄워 공개 HTTPS 주소(`https://<임의 이름>.trycloudflare.com`)를 만들고, QR에는 그 주소를 넣는다.

| 항목 | 값 |
|---|---|
| QR에 들어가는 주소 | `https://<공개 주소>/phone?s=<세션 ID>` |
| 프레임 전송 경로 | WebSocket `wss://<공개 주소>/ws/phone/<세션 ID>` |
| 세션 ID | 영문 소문자·숫자 6자리 (예: `a8f3k2`). web은 `GET http://<호스트>:8001/qr.svg`로 기본 세션 QR을 띄우면 된다 |
| 세션당 휴대폰 | 1대. 새 휴대폰이 같은 세션에 연결되면 이전 연결은 끊긴다 |

## 주고받는 메시지

연결 직후 gateway가 촬영 설정을 보낸다. 휴대폰은 이 값대로 찍어 보낸다.

```json
gateway → 휴대폰 (텍스트)
{"type": "config", "fps": 5, "max_side": 1024, "quality": 0.7}
```

휴대폰은 연결 직후 한 번 자기 정보를 보내고, 그 뒤로는 프레임을 바이너리 메시지로 보낸다.

```json
휴대폰 → gateway (텍스트, 1회)
{"type": "hello", "width": 1024, "height": 768, "user_agent": "..."}
```

| 메시지 | 형식 |
|---|---|
| 프레임 | 바이너리 메시지 1개 = JPEG 이미지 1장 |
| 이미지 형식 | JPEG, 긴 변 `max_side` px(기본 1024), 품질 `quality`(기본 0.7), 후면 카메라 |
| 보내는 주기 | 초당 `fps`장(기본 5). 네트워크가 밀리면 휴대폰이 그 장은 건너뛴다 |
| 크기 제한 | 한 장 2MB. 넘거나 JPEG가 아니면 gateway가 버린다 |

긴 변 1024px은 SAM 2 입력 크기(긴 변 1024)에 맞춘 값이다. 초당 5장은 화면 미리보기용이고, 실제 처리(전처리 → 추론)로는 gateway가 최신 프레임만 골라 보낸다 (`preprocessing-input.md`). 전처리도 긴 변을 1024로 맞추므로(`TARGET_SIZE`) 두 번 줄이지 않는다.

gateway는 받은 프레임마다 gateway 전체에서 1씩 늘어나는 `frame_id`와 받은 시각 `timestamp`(unix 초)를 붙여 뒤 단계로 넘긴다. 세션이 바뀌어도 번호는 되돌아가지 않는다 (visualizer가 번호 순서로 오래된 프레임을 버리기 때문).

## 연결 종료 코드

| 코드 | 뜻 |
|---|---|
| 4404 | 없는 세션 (QR을 다시 찍는다) |
| 4409 | 다른 휴대폰이 같은 세션에 연결됨 |

## 정할 것

- [ ] 긴 변 1024px, 초당 5장, 품질 0.7이 적당한지 (진아: 전처리 입력 크기와 함께 확인)
- [ ] 임시 터널 주소는 실행할 때마다 바뀐다. 고정 주소가 필요하면 Cloudflare 계정의 이름 있는 터널을 쓴다 (`GATEWAY_PUBLIC_URL`로 지정)
