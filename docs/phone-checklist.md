# 실제 휴대폰 확인 체크리스트

실제 휴대폰으로 ①~⑥ 전 구간을 확인한다. 순서대로 진행하며 "정상" 칸과 화면을 비교한다.

준비물: 인터넷에 연결된 PC, 휴대폰, 정상 과자와 깨진 과자, 무늬 없는 단색 배경(과자와 밝기 차이가 클 것).

| 단계 | 할 일 | 정상 | 아닐 때 |
|---|---|---|---|
| 1 | `docker compose up --build -d` | `docker compose ps`에서 5개 모두 `healthy` | `docker compose logs <서비스>` |
| 2 | PC에서 `http://localhost:8000` | `gateway 연결됨`, QR 표시 | QR 대신 `접속 주소 준비 중`이면 몇 초 기다린다. 계속되면 `http://localhost:8001/health`의 `tunnel` |
| 3 | 휴대폰으로 QR 찍기 | 휴대폰 `연결됨. 촬영을 시작하세요.`, 대시보드 `휴대폰 연결됨` | `세션이 끝났습니다`면 대시보드 새로 고침 후 다시 찍기 |
| 4 | "촬영 시작", 카메라 권한 허용 | 휴대폰 `촬영 중`, 초당 약 5장 | 브라우저의 카메라 권한 설정 |
| 5 | 대시보드 보기 | 받은 프레임이 늘고 오류 0, 마킹 화면이 2~3초 늦게 나옴 | 대시보드의 `마지막 오류` 문구 |
| 6 | 세로로 찍기 | 화면이 바로 서 있음 | |
| 7 | 가로로 찍기 (자동 회전 켬 / 끔) | 화면이 바로 서 있음 | 자동 회전을 끄면 90도 돌아가는 것은 알려진 한계 |
| 8 | 정상·깨진 과자 비추기 | 정상 `PASS`(초록), 깨진 것 `FAIL`(빨강), 가장자리 `WAIT`(회색) | 윤곽선이 안 생기면 배경 대비를 높인다 |
| 9 | 과자를 오른쪽 → 왼쪽으로 천천히 옮기기 | 검사선(세로선)을 지날 때 `누적 검사` +1, 불량이면 `누적 불량` +1 | 빨리 옮기면 세지 못한다 |
| 10 | "누적 초기화" | 누적 수 0 | |
| 11 | 휴대폰 "촬영 멈추기" | 대시보드 `휴대폰 미연결` | |

확인 후 휴대폰 기종·브라우저, 단계별 결과, 대시보드 성능 칸의 fps·지연 p95를 PR이나 팀 채널에 남긴다.
