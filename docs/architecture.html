연결

번호보내는 쪽 → 받는 쪽주소내용상태
⓪web → PC 브라우저GET http://<호스트>:8000/대시보드 HTML 한 장구현 (PR #5)
①휴대폰 → gateway미정카메라 프레임미정
②gateway ↔ preprocessingPOST http://preprocessing:8002/preprocess요청: JPEG/PNG 바이트 또는 {"frame_id", "image"} JSON
응답: 긴 변 1024px 이미지, 크기·배율, 과자 후보 박스·점		preprocessing 쪽 구현 (브랜치)
③gateway 또는 preprocessing → inference미정전처리 이미지와 후보형식과 보내는 쪽 모두 미정
④inference → visualizerPOST http://visualizer:8004/visualize원본 이미지, 과자별 윤곽선·원형도·PASS/FAIL제안 (visualizer 작성)
⑤visualizer → gatewayPOST http://gateway:8001/result마킹된 JPEG, 집계(화면 속·누적), 과자별 판정visualizer 쪽 구현, gateway 수신 미구현
⑥gateway → PC 브라우저ws://<호스트>:8001/ws/view⑤의 JSON 그대로제안, 브라우저 쪽 구현 (PR #5)
⑦PC 브라우저 → visualizerPOST http://<호스트>:8004/reset누적 수 초기화구현 (PR #4, #5)

제안 문서: services/visualizer/contracts/inference-visualizer.md(④), services/visualizer/contracts/visualizer-gateway.md(⑤⑥). preprocessing API: services/preprocessing/README.md(②).

주소 규칙

컨테이너 → 컨테이너②~⑤. Docker 네트워크 안에서 서비스 이름으로 부른다 (http://visualizer:8004). 컨테이너 안의 localhost는 자기 자신이다.
브라우저 → 컨테이너⓪ ⑥ ⑦. 브라우저는 Docker 네트워크 밖이라 호스트 주소와 포트로 부른다 (localhost:8004).
web 컨테이너HTML을 내려주는 일만 하고 다른 컨테이너를 직접 부르지 않는다. 화면의 실시간 데이터(⑥)와 초기화(⑦)는 브라우저가 직접 연결한다.
